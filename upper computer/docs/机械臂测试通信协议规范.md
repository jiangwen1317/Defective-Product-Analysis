机械臂测试通信协议规范（纯文字版）

一、通用规则
传输协议：所有指令均基于 TCP/IP 协议，采用 String（字符串）格式传输。
帧定界符：指令必须以字符 @ 开头，以字符 + 结尾。
大小写敏感：指令关键字（如 START_TEST）及 ErrorCode 的十六进制数值严格区分大小写（例如：START_TEST ≠ start_test；0A1B ≠ 0a1b）。固定占位符 00 及 Bitmask 中的 0/1 字符不涉及大小写。
分隔符：指令中各字段之间必须使用单个空格分隔，禁止使用逗号、制表符或换行符。

二、指令格式详解

@START_TEST 指令（Server → Client）
功能：服务端通知客户端启动指定 DUT 的测试流程。
格式：@START_TEST  +
字段定义：
    ：00（固定占位符）：严格为 ASCII 字符串 "00"，位于指令关键字与 Bitmask 之间，用于保持帧格式对齐。当前协议版本中该值恒为 "00"，不可省略、不可替换为其他数值。
    ：严格8位二进制字符串（仅含字符 0 或 1），从左至右依次对应 DUT #1 至 DUT #8。其中 1 表示对该 DUT 启动测试；0 表示跳过该 DUT，不进行测试。
示例：
    @START_TEST 00 11111111+ （启动全部8个DUT测试）
    @START_TEST 00 10100000+ （仅启动 DUT #1 与 DUT #3 测试）

@TEST_DONE 指令（Client → Server）
功能：客户端完成测试后，向服务端回传各 DUT 的错误码/状态码。
格式：@TEST_DONE         +
字段定义：
    ：00（固定占位符）：严格为 ASCII 字符串 "00"，需与 @START_TEST 中的固定占位符保持一致。
    ~ ：8个严格4位十六进制数（大写 A~F，0~9），空格分隔，从左至右依次对应 DUT #1 至 DUT #8。不足4位时，必须在前方补零至4位（例如：错误码为 904 时，必须发送 0904，禁止发送 904）。
示例：
    @TEST_DONE 00 1901 1902 1903 1904 0151 0401 0152 0904+
    字段解析：DUT #1 → 1901；DUT #2 → 1902；DUT #3 → 1903；DUT #4 → 1904；DUT #5 → 0151；DUT #6 → 0401；DUT #7 → 0152；DUT #8 → 0904（注意：必须为4位，不可省略前导零）。

三、关键约定
DUT 数量固定：系统始终支持且仅支持 8 个 DUT（编号 #1 ~ #8）。
顺序一致性：Bitmask 与 EC1~EC8 的排列顺序完全一致，均为最左侧 = DUT #1，最右侧 = DUT #8。
数值格式区分：固定占位符为 ASCII "00"；ErrorCode 字段为4位十六进制；Bitmask 字段为8位二进制（非十六进制）。
异常处理：若接收到的指令不符合上述格式（如位数错误、非法字符、缺少定界符等），接收方应丢弃该指令并记录日志，不得执行任何操作。

四、典型通信流程
Server 发送启动指令：@START_TEST 00 11111111+
Client 执行8个DUT测试。
Client 测试完成后回传结果：@TEST_DONE 00 1901 1902 1903 1904 0151 0401 0152 0904+

五、附录：快速校验清单（开发自查用）
Bitmask 长度：正确为 11111111（8位）；错误为 1111111（7位）、FF（十六进制）。
ErrorCode 补零：正确为 0904；错误为 904、0x0904、904h。
十六进制大小写：正确为 0A1B；错误为 0a1b、0A1b。
字段分隔符：正确为单个空格；错误为多个空格、Tab、逗号。
帧首尾字符：正确为 @...+；错误为缺少 @ 或 +、首尾有多余空格。
